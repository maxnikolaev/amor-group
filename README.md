## Структура папок

```
amor-group/
├── skills/          # Технические скиллы AI-девелопера
├── methods/         # Методологии и стандарты
│   └── sync-file-template.md      # шаблон sync-файла проекта
├── cases/           # Проекты
│   └── <YYYY-MM-DD> - <тип> - <название>/
│       ├── sync.md              # ← единый источник правды по проекту (статус/блокеры/шаги)
│       ├── pitch-deck/          # презентации (PDF, PPTX)
│       ├── материалы/           # документы, фото
│       │   └── research/        # исследования (рынок, аналоги, экономика)
│       ├── файлы проекта/       # финмодели, проекты домов
│       ├── from-tg-chat/        # файлы, присланные в Telegram-чат
│       ├── транскрибации/       # транскрипты разговоров (пишет бот)
│       └── log/                 # вехи, инциденты, корректировки модели
├── howtoadd.md      # как подключить свой ПК (инструкция для сотрудников)
└── README.md        # этот файл
```

### Ключевые файлы

- **`sync.md`** — единый источник правды по статусу проекта (что есть / блокеры / следующие шаги / цифры). Обновлять при каждом изменении. Шаблон — `methods/sync-file-template.md`.
- **`транскрибации/`** — только `.md`-файлы, имя `YYYY - MM DD - канал - участники - тема.md`. Каналы: `телефон`, `телеграм`, `встреча`, `зум`, `диктофон`, `Яндекс.Диск` и др.
- **`research/`** — исследования (рынок, нормативы, аналоги). **`log/`** — внутренние вехи, инциденты, корректировки.

## Как устроена работа

### Принцип хранения

| Где | Что хранится |
|-----|-------------|
| **GitHub (этот репо)** | Проекты, методология, транскрипты, документы — источник правды |
| **Сервер Hermes** | Технические файлы, секреты (`.env`, cookies), кэш, временные данные |

### Поток: транскрибация разговора

1. Кидаешь `@amorgroupteam_bot` голосовое / аудио / видео / ссылку (YouTube, Яндекс.Диск) с комментарием «проект, канал, участники, тема».
2. Бот скачивает → Deepgram → `.md`.
3. Сохраняет в `cases/<проект>/транскрибации/`, коммитит, присылает ссылку на GitHub.
4. Если проект не указан — спросит.

### Поток: файлы из Telegram-чата

1. Участник присылает файл в чат проекта.
2. Hermes сохраняет его в `cases/<проект>/from-tg-chat/` с именем `YYYY-MM-DD_HHmm_<кто>_<описание>.<ext>`.
3. Коммитит и пушит.

### Правила

- **`git pull` перед любой работой** — участники грузят файлы через GitHub Web напрямую, в обход сервера.
- **`sync.md`** — единый источник правды по проекту; обновлять при каждом изменении.
- **Секреты** (`.env`, cookies, ключи) — только на сервере, в git не коммитятся.
- **Транскрипты** — только `.md`, медиа/JSON в репозиторий не попадают.
- **Чужие файлы не удалять** — перемещать в `archive/`; не редактировать напрямую, создавать копию.
